# 프론트엔드 규칙 (Next 16 App Router, React 19, Tailwind 4)

디자인 값(토큰, 타입 스케일, 레일 그리드, 컴포넌트)의 설명은 `docs/design.md` 다. 실제 값의 원본은 `src/styles/globals.css` 의 토큰이고, 둘이 다르면 코드가 맞다(값을 바꾸면 문서도 같이 고친다).

## CSS 와 Tailwind 4 (tailwind.config 없음)

- CSS 는 3파일이다. `src/styles/globals.css`(토큰, Tailwind 매핑, 요소 기본값, 공용 클래스, 헤더/푸터 크롬)가 `./markdown.css`(글 머리와 글 끝, 글 본문, 코드 블록, 콜아웃, 다이어그램, 이미지, 목차), `./pages.css`(홈, /tech, /log, 404, 히어로 오브젝트) 순서로 import 한다. 토큰(`:root`)은 레이어 밖, 요소 기본값은 `@layer base`, 나머지는 `@layer components`.
- 색은 CSS 변수 토큰이다(`:root` 에 라이트, 다크는 `:root` 안의 `@variant dark` 한 블록에만 둔다. 커스텀 변형 `dark` 가 이를 시스템 다크(강제 라이트 아님)와 강제 다크(`data-theme="dark"`) 두 규칙으로 펼친다). 팔레트는 원본 blan19 Open Color gray(`--gray-0`…`--gray-11`, 라이트 배경 `#f8f9fa`, 다크 배경 `#16181b`)이고 색상(hue)은 없다. 강조는 잉크 대비(`--text`, `--ink`)와 굵기, 밑줄로만 한다. 빨강(`--danger`, `--danger-text`)은 오류 표시(404, error 코드 라벨)에만, slate(`--sh-string`, `--sh-number`)는 신택스 리터럴에만 쓴다. 의미 토큰: `--bg`, `--bg-subtle`, `--code-bg`, `--line`, `--line-strong`, `--selection`, `--text`, `--text-2`, `--text-3`, `--text-4`(장식 전용), `--ink`, `--focus`, `--danger`, `--danger-text`, `--img-filter`, `--shadow`, `--scrim`, `--scrim-strong`, `--object`, `--object-alpha`, `--diff-add`, `--diff-del`, `--diff-del-hl`(강조 줄 안의 `--diff-del`, 다크는 대비 때문에 `--text-2`), `--sh-*`. 크기/굵기/레이아웃 토큰: `--fs-display|title|body|ui|meta|code`, `--fw-regular|medium|semi|bold`(400/500/600/650), `--rail`, `--col-gap`, `--main`, `--gutter`, `--obj-w`, `--radius`, `--radius-sm`, `--underline-offset`(밑줄 링크와 목록 제목 hover 밑줄), `--ease`. 다른 변수를 참조하는 파생 토큰(`--line-hl-bg`)은 `:root` 에 한 번만 둔다. 새 색은 라이트 값과 `@variant dark` 블록에 함께 넣는다. 이전 MARGIN 토큰 이름(`--accent`, `--muted`, `--surface`, `--marker`, `--serif` 등)은 없다. 하드코딩 hex 는 `globals.css` 토큰, `src/lib/theme.ts` 의 `THEME_COLORS`(`--bg` 와 같은 값), OG 카드(`src/lib/og-image.tsx`), 파비콘 `src/app/icon.svg`(CSS 변수를 못 쓴다)에만 둔다.
- `@theme inline { --color-*: initial; … }` 로 기본 팔레트를 지우고 토큰만 유틸리티로 연결했다: `bg`, `subtle`, `line`, `line-strong`, `text`, `text-2`, `text-3`, `ink`, `danger`(예: `bg-subtle`, `text-text-3`, `border-line`). `white`, `black`, `red-500` 같은 클래스는 생성되지 않으며 오류도 나지 않는다. 폰트 `font-sans`/`font-mono`, `ease-soft`, `rounded-box` 도 있다(`font-serif`, `ease-paper`, `rounded-code` 는 없다). TSX 에서 쓰는 유틸리티는 현재 `layout.tsx` 의 건너뛰기 링크(`focus:bg-text focus:text-bg` 등)뿐이다. 신택스 색(`--sh-*`)은 유틸리티가 없다.
- 색 토큰이 테마를 따라 바뀌므로 `dark:` 는 예외적으로만 쓴다(G3 포팅 뒤에는 쓰는 곳이 없다. 다크 코드 블록은 배경 한 단계 차이와 `--line` 테두리로 구분한다). `dark` 는 커스텀 변형이라 시스템 다크와 강제 다크(`data-theme="dark"`) 둘 다에 걸리고 강제 라이트에서는 꺼진다.
- `hover:` 는 `@custom-variant hover (&:hover)` 로 v3 방식(터치 기기에서도 적용)이다.
- 브레이크포인트는 Tailwind 기본 그대로다(`md` 768px, `xl` 1280px 만 쓴다). `<1280` 은 한 열(최대 688px), `≥1280` 은 레일 그리드(왼쪽 레일 176 · 간격 56 · 본문 688 = 920px). 레일에는 섹션 라벨(최근 글, 연도, 기록 날짜 등)과 글 목차가 들어가고 오른쪽 여백 열은 없다. 구조는 `.site-wrap`(여백 `--gutter` 16px, ≥768 32px) > `.rail-grid` > `.rail-side`(레일, `<1280` 에서는 본문 위로 쌓임) / `.rail-main`(본문 열).
- 공용 클래스(`globals.css` 만 최상위로 정의, 다른 CSS 파일은 재정의하지 않는다): `.site-wrap`, `.rail-grid`, `.rail-side`, `.rail-main`, `.rail-label`, `.page-head`, `.page-h1`, `.page-lede`, `.code-label`, `.u-link`, `.link-row`, `.ext`, `.mono`, `.tnum`, `.icon`, `.icon-btn`, `.wordmark`, 크롬(`.site-header`, `.head-grid`, `.site-nav`, `.nav-link`, `.theme`, `.theme-menu`, `.site-footer`, `.foot`, `.err-links`). 이전 MARGIN 클래스(`.site-col`, `.double-rule`, `.kicker`, `.page-title`, `.btn-outline`, `.seal*` 등)는 없다. `mark` 와 `::selection` 은 `--selection` 회색 배경이다(형광펜 없음). 도장(seal)은 어디에도 쓰지 않는다.
- 셀렉터 범위 규칙: `markdown.css` 와 `pages.css` 의 모든 규칙은 각 파일 머리 주석에 적힌 루트 클래스로 시작한다(`markdown.css`: `.post-grid`, `.post-head`, `.post-main`, `.post-body`, `.post-end`, `.end-sec`, `.end-label`, `.refs`, `.pn-wrap`, `.pn`, `.comments`, `.code-block`, `.callout`, `.diagram`, `.img-fig`, `.zoom-dlg`, `.toc-details`, `.toc-rail`, `.toc-pill`, `.toc-sheet` / `pages.css`: `.home-intro`, `.home-sec`, `.idx-list`, `.idx-row`, `.log-line`, `.tag-filter`, `.tech-list`, `.list-year`, `.log-entry`, `.nf`, `.hero-obj`, `.empty-note`, `.more-link`, `.now-line`). `.cnt`, `.views`, `.chev`, `.rule`, `.active`, `.read`, `.show`, `.pct`, `.go`, `.lede` 같은 범용 이름은 루트의 후손으로만 쓴다. `.hl` 은 쓰지 않는다: 코드 줄은 `.line-hl`/`.line-add`/`.line-del`, 목록 제목 형광펜(`.title-hl`)은 없다.
- 다른 파일의 루트 클래스를 빌려 쓸 수 있다: 글 끝 "관련 글"(`ui/related-posts`)은 `markdown.css` 의 `.end-sec`/`.end-label` 안에 `pages.css` 의 `.idx-list`(`ui/post-row`, 홈 목록과 같은 행)를 그대로 쓰고 새 CSS 가 없다.
- 누르는 영역(탭 타깃): 작은 글자 링크는 보이는 글자 크기·간격·정렬을 그대로 두고 투명한 `::before`(`position: absolute`, 링크에 `position: relative`)로 높이 44px 까지 넓힌다(`.nav-link` 는 가운데 기준 너비 44px 이상, `.foot a`, `.home-intro .intro-links a`, `.nf .nf-links a`, `.more-link a`, `.post-head .post-meta .meta-tag` 는 높이 44px). 좌우는 이웃 간격의 절반까지만 넓혀 인접 타깃과 겹치지 않게 하고, 여러 줄로 감기는 묶음(`.tag-filter a`)은 위아래도 간격의 절반까지만(약 28px) 넓힌다. 세로로 붙은 목록(목차 링크)은 패딩이 이미 줄 간격을 다 채워 넓힐 곳이 없다. `::after` 는 `.ext`(↗)가 쓰므로 히트 영역에 쓰지 않는다.
- 각주 라벨 `h2.end-label` 이 `.post-body` 안에 생긴다. 본문 h2 규칙은 `.post-body h2:not(.end-label)` 로 쓴다. `.end-label`/`.end-sec` 의 모양은 `markdown.css` 만 정의한다.
- 클래스 이름 금지 목록: Tailwind 4 는 소스에서 찾은 문자열을 유틸리티로 만들기 때문에 커스텀 클래스가 유틸리티 이름과 겹치면 안 된다. `ring`, `shadow`, `collapse`, `contents`, `table`, `grid`, `flex`, `hidden`, `block`, `inline`, `container`, `truncate`, `italic`, `underline`, `border`, `rounded`, `static`, `fixed`, `sticky`, `relative`, `absolute`, `visible`, `invisible`, `prose`, `outline`, `filter`, `blur`, `invert`, `uppercase`, `lowercase`, `capitalize`, `isolate`, `ordinal`, `transform`, `transition`, `col`, `row` 를 커스텀 클래스로 쓰지 않는다(G3 목업의 `.wrap`→`.site-wrap`, `.grid`→`.rail-grid`, `.rail`→`.rail-side`, `.main`→`.rail-main`, `.label`→`.rail-label`, `.code`→`.code-block`). `sr-only` 는 Tailwind 것을 쓴다.
- Preflight 주의: `ol, ul { list-style: none }`, 헤딩 `font-size: inherit`, `a { color: inherit; text-decoration: inherit }`, `img { display: block }` 이 걸려 있다. 글 본문 CSS 는 목록 마커, 링크 밑줄, 헤딩 크기를 전부 명시한다. `@tailwindcss/typography`(`.prose`)는 쓰지 않는다.
- 클래스 이름은 소스에 문자열 그대로 써야 감지된다. `` `text-${size}` `` 같은 동적 조합은 생성되지 않는다(CSS 파일에 직접 정의한 클래스를 조합하는 것은 괜찮다).
- `markdown.css` 의 마크다운 출력 루트 직계는 p, h2–h5, ul, ol, figure, aside, blockquote, div.table-wrap, hr, section.footnotes 뿐이다. 직계 선택자(`>`)는 블록 리듬에만 쓰고 나머지는 후손 선택자로 쓴다.

## 폰트 (`src/app/fonts.ts`, layout 의 `<html>` className)

- `pretendard`: `next/font/local`, `src/fonts/PretendardVariable.subset.woff2`(가변 1개, weight 45–920, preload, 약 650KB) → `--font-pretendard`. 본문과 UI. `adjustFontFallback` 은 기본값(size-adjust 대체 글꼴)으로 둔다.
- Pretendard 서브셋: pretendard@1.3.9 의 `dist/public/variable/PretendardVariable.ttf` 를 패키지의 공식 `subset_glyphs.txt`(KS X 1001 한글 2,350자 + 그 밖 한글 430자 + 라틴, 기호 등) ∪ 저장소에서 쓰던 `＇` `＂` `↩` 로 줄였다(3,732 코드포인트, 굵기 축과 GSUB/GPOS 기능 전부 유지, 원본 2,057,688B). 코드포인트 목록은 `src/fonts/PretendardVariable.subset.unicodes.txt` 다. 다시 만들 때는 fontTools(`fonttools[woff]`, brotli 포함)로 `pyftsubset PretendardVariable.woff2 --unicodes-file=src/fonts/PretendardVariable.subset.unicodes.txt --layout-features='*' --name-IDs='*' --name-languages='*' --notdef-outline --hinting --flavor=woff2 --output-file=src/fonts/PretendardVariable.subset.woff2` 를 실행한다(원본 전체 woff2 는 `git show c1ded39:src/fonts/PretendardVariable.woff2` 로 꺼낼 수 있다). 결과는 645,672B 이고 원본과 글리프 외곽선, 글자 폭, 굵기 축, GSUB 기능이 같다. 목록 밖 글자(예: `꿻`)는 Pretendard 가 아니라 `--sans` 스택의 시스템 폰트로 그려진다(빠지지는 않지만 모양이 다르다).
- 글에 목록 밖 한글이 있는지 확인: `node -e 'const fs=require("fs"),p=require("path"),s=new Set();for(const l of fs.readFileSync("src/fonts/PretendardVariable.subset.unicodes.txt","utf8").trim().split("\n")){const[a,b=a]=l.split("-").map(h=>parseInt(h,16));for(let c=a;c<=b;c++)s.add(c)}for(const f of fs.readdirSync("contents",{recursive:true}).filter(f=>f.endsWith(".mdx")))for(const ch of new Set(fs.readFileSync(p.join("contents",f),"utf8")))if(/\p{Script=Hangul}/u.test(ch)&&!s.has(ch.codePointAt(0)))console.log(f,ch)'`(출력 없음 = 전부 포함). 나오면 그 글자를 목록에 넣고 서브셋을 다시 만들거나 대체 글꼴로 두는 것을 받아들인다.
- `plexMono`: `next/font/google` IBM Plex Mono 400/500 → `--font-plex-mono`. 날짜, 번호, 코드, 메타.
- 글꼴은 sans(Pretendard) 하나와 메타용 mono 뿐이다(세리프 없음). CSS 는 `--sans`, `--mono` 스택(`globals.css` `:root`)을 쓴다. 빌드 때 Google Fonts 를 내려받으므로 오프라인에서는 `next build` 가 실패한다.
- 제목, 본문, 인용, UI 는 모두 Pretendard 다. 날짜·읽는 시간·조회수·순위·태그 필터·코드 머리 같은 메타는 Plex Mono 다. 굵기는 400/500/600/650 만 쓰고 600 은 목록 제목(홈, /tech, 많이 읽힌 글)과 `em` 에만 쓴다.
- 한글 `italic` 은 쓰지 않는다(`em` 은 굵기 600 으로 표시). `mark` 는 회색 배경(형광펜 없음).

## 테마 (system / light / dark)

- `src/app/layout.tsx` 의 `<head>` 인라인 스크립트(`THEME_INIT`)가 첫 페인트 전에 `<html>` 에 `data-js`(JS 있음 표시)를 붙이고, localStorage `theme` 가 `light`/`dark` 면 `data-theme` 를 붙인다. system 은 속성 없이 CSS 미디어쿼리가 처리한다. `<html suppressHydrationWarning>` 이다.
- 테마 색(`THEME_COLORS`)은 `--bg` 와 같은 `#F8F9FA`/`#16181B` 다.
- `src/lib/theme.ts`(브라우저 전용 함수, `"use client"` 아님. 서버에서 import 해도 호출하지 않으면 안전): `ThemePref`, `ResolvedTheme`, `THEME_STORAGE_KEY`("theme", 인라인 스크립트와 같은 값), `THEME_EVENT`(`blan19:themechange`), `THEME_COLORS`, `readThemePref`, `resolveTheme`, `syncThemeColor`, `setThemePref`, `subscribeResolvedTheme`. `THEME_INIT` 은 `THEME_STORAGE_KEY` 를 문자열로 넣어 만들므로 키를 바꾸면 따라간다.
- `ui/theme-toggle` 은 `useSyncExternalStore`(서버 스냅샷 "system")로 설정을 읽고 `setThemePref` 로 바꾼다. 테마에 따른 색은 전부 CSS 변수로 처리하고 React 상태로 계산하지 않는다. CSS 로 못 바꾸는 것(mermaid, utterances iframe, 홈 히어로 캔버스의 색 읽기)만 `subscribeResolvedTheme` 로 따라간다.
- `viewport.themeColor` 의 두 `<meta name="theme-color">` 는 OS 설정만 따르므로 `syncThemeColor` 가 강제 테마일 때 덮어쓴다(`setThemePref` 안, 토글 마운트 때 1회).
- `[data-js]` 는 JS 가 있을 때만 켜지는 CSS(코드 블록 접힘과 "전체 보기" 버튼)에 쓴다. JS 가 없으면 코드 전체가 보인다.

## 글 렌더러 (`src/lib/markdown/`, `ui/post-body`)

- `renderMarkdown(key, markdown)`(`index.ts`, 서버 전용)이 unified 로 HAST 를 만들어 `{ hast, toc }` 를 돌려준다. 모듈 LRU 캐시(`Map`, 키 `${slug}:${sha1(본문)}`, 50개. 실패한 promise 와 코드 블록을 평문으로 대체한 렌더(`file.data.highlightDegraded`)는 지운다). `ui/post-body` 가 `hast-util-to-jsx-runtime` 으로 렌더하고 `figure`/`aside`/`a`/`img` 만 컴포넌트로 바꾼다(`components` 맵은 모듈 상수).
- 플러그인 순서: `remark-parse` → `remark-gfm` → `remark-shift-headings` → `remark-alerts` → `remark-rehype`(`allowDangerousHtml`, 각주 라벨 "각주" `h2.end-label`) → `rehype-raw-to-text` → `rehype-safe-urls` → `rehype-image-figures` → `rehype-code-blocks`(async) → `rehype-tables` → `rehype-slug` → `rehype-collect-toc` → `rehype-heading-anchors` → `rehype-footnote-section`. 커스텀 플러그인은 파일 하나에 하나, 이름 = 파일명.
- raw HTML 은 렌더하지 않는다(`raw` 노드를 같은 글자의 텍스트로 바꾼다). `a[href]`, `img[src]` 는 react-markdown `defaultUrlTransform` 규칙을 따른다: 콜론이 없거나 첫 콜론이 첫 `/`·`?`·`#` 보다 뒤면(상대 URL) 그대로, 그 밖에는 http, https, mailto 만 남기고 나머지(`javascript:` 등)는 빈 값.

## 히어로 오브젝트 (`ui/hero-object`, `ui/hero-canvas`, `src/lib/laptop.ts`)

- 홈 소개 옆(`<HeroObject mode="laptop" seed="blan19" animate />`)과 404(`mode="scatter" seed="404"`, `animate` 없음)의 장식용 점묘 노트북이다(화면에 재생 글리프와 재생 막대). 404 는 같은 노트북이 흩어진 분해도 정지 화면이다. `figure.hero-obj[aria-hidden]` 이고 정보나 링크를 담지 않는다.
- `src/lib/laptop.ts` 는 DOM 없는 순수 기하(점 생성 `buildLaptop`, 투영 `projectLaptop`, 자세 `laptopPose`/`laptopYawAt`/`laptopScrubAt`, 불투명도 칸 `laptopBucket*`, 시드 `hashSeed`, 서버 SVG 경로, 가로 빈 폭, 맞춤을 돌려주는 `laptopSvg`. 맞춤 계산 `laptopFit` 은 모듈 안 함수이고 `laptopSvg` 의 `fit` 은 `LaptopScale`(`s`, `cx`, `cy`)이다)라 서버와 클라이언트가 같이 import 한다. `server-only` 를 넣지 않는다. 같은 (mode, seed) 는 같은 모양이다(난수는 시드 고정 mulberry32, `Math.random` 없음). 홈 점 수는 약 1700개(1800 이하 유지).
- 밝기 위계: 화면 안에서는 재생 글리프(테두리 1.0, 채움 0.85)와 재생 막대의 지난 구간(w 1.0), 헤드(작은 해바라기 원판)만 밝다. 하판 윗면 모서리와 덮개 테두리는 0.95, 트랙패드 0.7, 카메라 점 0.6, 자판 0.55(1u 키 = 점 2개, 질감), 바닥 모서리 0.4(흐린 한 줄), 화면 점 격자 0.30–0.45. 불투명도 0.04 이하인 점은 맞춤 경계와 그리기에서 뺀다.
- `ui/hero-object`(서버)가 같은 점을 불투명도 칸(`LAPTOP_BUCKETS` 12)별 `<path>` SVG 로 먼저 그린다. JS 가 없거나 캔버스가 뜨기 전에도 이것이 최종 이미지다. `animate` 일 때만 클라이언트 섬 `ui/hero-canvas` 를 넣는다(404 는 JS 0).

SVG 와 캔버스가 같이 움직여 교차 때 튀지 않는다. 상자는 최대 약 34px 열 밖으로 나가지만 ≥768 의 열 바깥 여백(768px 에서 40px)보다 작아 가로 스크롤이 없다. 기하를 바꿔 빈 폭이 커지면 이 여유를 다시 확인한다.
- 움직임: yaw = −0.42 + 0.16·sin(2πt/46s), 재생 막대는 72초에 한 바퀴(1 → 0 으로 돌 때 지난 구간을 1.2초 동안 흐린다). 시차는 yaw ±0.07 / pitch ±0.05, 드래그는 yaw 오프셋 ±0.35, pitch 는 기본 ±0.12 까지(덮개 뒷면이 보이지 않게). 맞춤은 흔들림 + 시차 범위만 덮으므로 드래그 끝(크게 왼쪽 yaw + 아래 pitch)에서는 몇 px 가 상자 밖으로 잘린다(의도한 절충).
- 캔버스 규칙: 화면 안이고 탭이 보일 때만 그린다(IntersectionObserver, visibilitychange), 30fps 상한, 입력 없이 40초가 지나면 멈춘다(다시 시작하면 t 를 이어서 자세가 튀지 않는다), `prefers-reduced-motion` 이면 SVG 와 같은 t = 0 정지 프레임 하나(흔들림, 재생 막대, 시차 없음, 정밀 포인터 드래그로만 돌릴 수 있다. 설정이 바뀌면 t = 0 자세로 되돌린다), 포인터 시차와 드래그 회전은 정밀 포인터(`pointer: fine`)에서만(터치는 스크롤을 잡지 않는다, `touch-action: pan-y pinch-zoom`), DPR 상한 2(DPR 이 바뀌면 다시 그림). 점은 불투명도 칸마다 path 하나 + fill 하나로 그린다. 색과 최대 불투명도는 CSS(`color: var(--object)`, `--object-alpha`)에서 읽고 `subscribeResolvedTheme` 로 테마가 바뀌면 다시 읽는다. 리스너는 `AbortController` 하나로, observer 와 rAF 는 dispose 에서 모두 해제한다.
- 기하나 기본 자세(`LAPTOP_YAW0`, `LAPTOP_PITCH`, `LAPTOP_PROGRESS0`)를 바꾸면 서버 SVG 와 캔버스 첫 프레임이 함께 바뀐다. 파비콘 `src/app/icon.svg` 는 이전 히어로였던 점묘 매듭을 찍어 둔 정적 파일이고 노트북과 무관하다.

## 컴포넌트

- 기본은 Server Component 다. `"use client"` 는 `src/app/error.tsx`, `ui/nav-links`(usePathname), `ui/theme-toggle`, `ui/copy-button`, `ui/code-fold`, `ui/mermaid`, `ui/post-image`, `ui/toc-spy`, `ui/comment`(utterances iframe), `ui/hero-canvas`(홈 히어로 노트북 캔버스) 뿐이다. 클라이언트 경계는 최소로 유지한다. `ui/icon` 은 훅이 없어 양쪽에서 쓴다. MARGIN 때의 `ui/seal`(도장), `ui/author-card`, `ui/copy-link`, `ui/post-tags`(글 태그는 `ui/post-header` 메타 줄의 `#태그` 링크), `markdown/rehype-sidenotes` 는 지웠다.
- 클라이언트 컴포넌트 린트: `eslint-config-next` 의 `react-hooks/set-state-in-effect`, `refs`, `purity`, `globals`, `immutability`, `static-components` 가 error 다. effect 본문에서 `setState` 를 바로 부르지 않고(이벤트 핸들러, `await` 뒤, observer/rAF/`setTimeout`/구독 콜백 안에서만), 외부 값(테마 설정, matchMedia)은 `useSyncExternalStore` 로 읽고, props 변경 리셋은 부모의 `key` 로 한다. 렌더 중 `ref.current` 읽기/쓰기, `Date.now()`/`Math.random()`, 렌더 함수 안 컴포넌트 정의를 하지 않는다. `ui/toc-spy` 는 활성 항목을 React 상태가 아니라 DOM 에 직접 쓴다(진행률/퍼센트는 없다). 스크롤 없이 헤딩이 밀리는 경우는 `#post-body`, `#post-head` 의 ResizeObserver 가 잡는다(IntersectionObserver 는 쓰지 않는다). `ui/hero-canvas` 는 React 상태 없이 effect 하나가 캔버스를 명령형으로 다룬다.
- Cache Components 의 Activity 로 떠난 페이지가 `display:none` 으로 DOM 에 남는다(최대 3개, effect 는 정리 후 다시 실행). 그래서 id 와 셀렉터가 겹칠 수 있으니 클라이언트 컴포넌트의 DOM 조회는 자기 루트(`.site-wrap`) 안으로 한정한다. `TocSpy` 가 그렇게 하고, 글 안 `a[href^="#"]` 클릭에서 그 id 의 첫 요소가 다른 `.site-wrap` 에 있으면 보이는 글의 대상으로 `scrollIntoView` 후 `pushState` 한다(겹치지 않으면 브라우저 기본 동작).
- 댓글은 `<Comment key={slug} />` 로 쓴다. `ui/comment` 는 utterances `client.js` 를 실행하지 않고 `utteranc.es/utterances.html` iframe 을 직접 렌더한다(쿼리는 client.js 와 같은 비공개 계약). src 는 댓글 영역이 가까워질 때 effect 에서 붙이고, `message` 리스너 하나로 높이를 맞추며(cleanup 에서 해제), 로그인 뒤 돌아온 `?utterances=` 세션을 localStorage 에 저장하고 주소에서 지운다. 테마는 postMessage `set-theme` 으로 따라간다.
- 조회수 접근은 server-only 인 `src/lib/views.ts` 하나이고 Server Action 은 없다(`"use server"` 파일이 없다).
- DB 를 읽는 컴포넌트는 `ui/view-count`(`ArticleViews`, `RowViews`, fallback `ViewsPending`)와 `ui/most-read`(`MostRead`, fallback `MostReadPending`)의 패턴을 따른다: `<Suspense>` 안에서만 쓰고, `await connection()` 은 try 밖(views.ts 함수도 각자 부른다), 쿼리만 try/catch, catch 첫 줄 `unstable_rethrow(error)` 후 `null`. `unstable_rethrow` 는 Next 16.4 의 prerender 중단, hanging-promise 오류를 다시 던지기 위해 계속 쓴다. `RowViews` 는 로그를 남기지 않는다: React `cache` 인 `getViewMap`(`src/lib/views.ts`)이 실패를 요청당 한 번 로그하고 다시 던진다(행마다 같은 오류가 찍히지 않게). `MostRead` 도 로그하지 않는다: 캐시 경계를 넘은 오류는 메시지가 가려지므로 `getTopViews` 안에서 원래 오류를 로그한다. 실패하면 그 칸이나 섹션만 사라진다(`app/error.tsx` 는 진짜 버그용).
- 서버 전용 모듈(`src/lib/posts.ts`, `views.ts`, `prisma.ts`, `feed.ts`, `og-image.tsx`, `markdown/index.ts`, `markdown/shiki.ts`, `markdown/feed-html.ts`, `markdown/code/highlight.ts`)은 첫 줄 `import "server-only";` 다. 클라이언트나 검사기도 읽는 `config.ts`, `laptop.ts`, `figures.ts`, `page-ids.ts`, `languages.ts`, `types.ts`, `image-meta.ts` 에는 넣지 않는다.
- Next 16: 페이지와 `generateMetadata` 의 `params`/`searchParams` 는 `Promise` 타입이고 `await` 한다. route handler 에도 같은 규칙이 적용된다. `error.tsx` 는 `retry` prop 을 받는다. `/tech` 는 searchParams 를 `<Suspense>` 안에서만 읽는다. 정적 셸의 fallback 은 선택 표시 없는 `TagFilter`(`pending`)와 `aria-busy` 전체 목록이고 태그 링크로 이동할 때도 잠깐 보인다. `/tech/[slug]` 는 params 를 Suspense 밖(페이지 맨 위)에서 await 해 목록에 없는 slug 가 404 상태 코드를 유지한다.
